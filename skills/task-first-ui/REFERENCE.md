# Product-Minded UX/UI — Reference

Supplements `SKILL.md`.

## Generic-AI design patterns to avoid by default

- purple or blue gradient hero sections;
- glassmorphism or blurred translucent panels;
- uniformly rounded cards with soft shadows;
- oversized vague hero copy;
- decorative dashboard charts or fake metrics;
- three interchangeable feature cards;
- carousels for content users need to compare or find;
- decorative illustrations or icons used to fill weak hierarchy.

These are not universal bans. Use one only when the product, content, or established visual system provides a clear reason.

## Adapt the deliverable

### For design work

Provide the product frame, the proposed hierarchy or flow, the key states, and only the non-obvious rationales. Use wireframes or multiple directions only when they materially improve the decision.

### For implementation work

Briefly state:

1. what the user and product need;
2. the minimal design serving that need;
3. why any non-obvious element is present.

Then implement and verify. Do not narrate routine styling choices.

### For review work

Lead with findings ordered by user impact. For each finding, identify the evidence, affected task or user, and smallest credible fix. Distinguish confirmed defects from product assumptions. Avoid prescribing a wholesale redesign when a local fix solves the issue.

If no material issue is found, say so and note any unverified risk instead of inventing critique.
