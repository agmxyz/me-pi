The delegate correlates and records that observation separately while preserving `effect: unknown` on a failed call; it does not invent `effect: partial`. Partial output is not evidence of a partial side effect. Denied, completed, and unknown effects are handled conservatively: unknown or non-completed effects refuse replay and acceptance. The absence of a runtime partial-side-effect classification remains an explicit capability limit, not evidence that a partial effect occurred or permission to replay.

The accepted contract specifies named/adopted coordinator contracts as runtime restriction inputs, not as independently authenticated approvals; real approval and reference freshness remain coordinator-owned. ### Endpoint evidence correction (integrated Standards `bg83`)

The installed Pi 1.4.0 runtime does not make `ModelRegistry.find()`'s catalog `baseUrl` the effective request URL in all cases: `ModelRuntime.prepareRequest()` replaces it with `auth.baseUrl` from request-time auth, and GitHub Copilot's OAuth `toAuth()` derives a credential-specific endpoint. `ModelRegistry.getApiKeyAndHeaders()` resolves credentials and is not used for this check; the SDK exposes no credential-free effective-endpoint accessor. The GitLab Duo custom-provider example also changes the request model's base URL inside its stream implementation.

The parent registry snapshot does not bind a fresh child's effective destination: `pi --model` loads its own configuration and resolves request-time authentication after the prompt is supplied. Although some transports use catalog `model.baseUrl`, request-time auth can replace it, OAuth can derive a credential-specific endpoint, and provider extensions can alter the request model's URL. The SDK exposes no supported credential-free accessor or endpoint-only pin at the child request boundary. Therefore the delegate now disables all cross-model fallback, including transports whose catalog metadata appears direct or matching. It does not read credentials to try to establish the endpoint, change model/provider authority, or claim that parent metadata pins the child. The first selected candidate and exact-model behavior remain; shared budgets and provenance still apply to that one dispatched child.

This is a safe fail-closed implementation limitation, not a change to the accepted A2 contract. It does not satisfy the original functional requirement to enforce frozen run-scoped model/provider/destination/data authorization while allowing eligible fallback; that acceptance remains unmet unless separately changed by the user. Re-enable only when a supported effective-endpoint enforcement mechanism exists at the child's request boundary, with regression coverage.

## Decided boundaries

- This is the intentional safety migration of legacy fallback authorization/classification, distinct from A5's backward-compatible review-pool selection. A5 may ship first with existing fallback behavior; after A2 all pools obey A2. A2 does not require A5.
- Exact-model instructions stay exact; configured pools alone do not authorize fallback. Quota/billing exhaustion is not transient availability. Unknown cause/effects fail closed for replay and acceptance.
- No telemetry subsystem, broad event schema, new consent service/UI, runtime ledger, automatic retry, account/provider/quota evasion, or malicious-code-sandbox claim.
- A2 may be implemented in small bounded slices through the owning interfaces/tests. Keep those slices within A2; they do not require new tickets, graph machinery, panels, or routine human approval. Preserve current stop-on-guard/worker-limit policy until A4.
